## 1. D63''': los signos de la regla de inclusión

**El ejemplo rehecho desde cero:**
- Atestación del día 27: 1.500 (liquidada).
- Compra −1.000 ejecutada el 28, con el lado del efectivo de liquidación **desconocida**.
- Atestación del día 30: 1.500.
- Notación: x = efecto sobre L del lado desconocido = −1.000.

| Escenario | L(30) | Previsto = A₂₇ + L(30) − L(27) | r = A₃₀ − previsto |
|---|--:|--:|--:|
| N: no liquidada el 30 | 1.500 | 1.500 + 0 = 1.500 | **0** |
| S: liquidada el 30 | 500 | 1.500 − 1.000 = 500 | **+1.000** |

**El conjunto posible es {0, +1.000}.** Cuando se sabe que el valor es el día 2, el escenario real es N → **r = 0**.

**[X] El error:** escribí «r ∈ [−1.000, 0]», que es el resultado de una **venta** de +1.000, no de una compra.

**La fórmula general, comprobada con los dos signos.** Con r₀ = el residuo suponiendo que no se ha liquidado ningún lado desconocido, y S = el conjunto de los que sí:

```
r(S) = A_k − [base + Σ_{j∈S} x_j] = r₀ − Σ_{j∈S} x_j
```

- **Compra** (x = −1.000): r ∈ {r₀, r₀ + 1.000} ✓ (E2).
- **Venta** (x = +1.000): r ∈ {r₀, r₀ − 1.000} ✓ (la venta del informe anterior: {0, −1.000}).
- **Los extremos** [r₀ − Σ_{x>0} x, r₀ − Σ_{x<0} x] **son correctos con los dos signos.**

**[X] El error grave:** el **intervalo** incluye valores **imposibles**. Ejemplo: r₀ = −300 y un lado desconocido x = −1.000.
- Valores posibles: {−300, +700}.
- El intervalo [−300, +700] **contiene el 0**, y la regla anterior decía «**puede cuadrar**».
- **Es falso:** hay una discrepancia real (de −300 o de +700).

**La corrección:** usar el **conjunto exacto** de residuos posibles.

```
R_posibles = { r₀ − Σ_{j∈S} x_j : S ⊆ U' }    (U' = unidades de liquidación, sección 2)
«puede cuadrar» ⇔ 0 ∈ R_posibles ⇔ ∃ S: Σ_{S} x_j = r₀
```

- Se muestran el **mínimo** y el **máximo** del conjunto, **más** si el 0 es posible o no.
- **Coste:** con |U'| ≤ 20 se pueden recorrer los 2²⁰ ≈ 1 millón de casos (en céntimos enteros y en milisegundos). En la práctica, un tramo tiene pocos lados sin liquidación conocida.
- **Si |U'| > 20:** se muestran solo los extremos, con «**no comprobado si puede cuadrar**». **Nunca** «puede cuadrar».

## 2. Dependencias entre lados: unidades de liquidación

**La hipótesis de independencia es falsa** en tres casos:

| Caso | Por qué no es independiente | Tratamiento |
|---|---|---|
| Una compra y su comisión registradas como dos hechos | Se liquidan juntas | **Una sola unidad de liquidación**, con x = la suma |
| Una transferencia dividida en importe + comisión, o varias líneas de una misma orden | Se liquidan juntas | Una sola unidad (las vincula `operacion_id` o un vínculo) |
| Un apunte manual sin `fecha_valor` y una línea del extracto **que todavía no están vinculados** y pueden ser el mismo movimiento | No son dos posibilidades: **o** es el mismo **o** son distintos | **Ese tramo no se concilia** («revisar posible duplicado») **hasta que se resuelva la propuesta.** Eliminar duplicados va **antes** de conciliar |
| Una transferencia entre dos cuentas tuyas | Cada cuenta se concilia **solo con su propio lado**, así que la independencia **entre cuentas** no cambia el residuo de ninguna | Sin cambios. La restricción «el destino no se liquida antes que el origen» solo importaría en una vista conjunta, que no se presenta como una cifra |

**U'** = el conjunto de **unidades** (no de lados) con liquidación desconocida en el tramo, de esa cuenta.

**Ejemplo 1: compra + comisión como dos hechos.**
- A₂₇ = 1.500 · compra −1.000 · comisión −5, las dos el 28 y sin liquidación conocida · A₃₀ = **1.495**.
- r₀ = 1.495 − 1.500 = **−5**.

| Modelo | Valores x | R_posibles | ¿Puede cuadrar? |
|---|---|---|---|
| Lados independientes (incorrecto) | {−1.000, −5} | {−5, 0, +995, +1.000} | **«Sí»** (la comisión liquidada sin la compra) ✗ **es imposible** |
| Una sola unidad (correcto) | {−1.005} | {−5, +1.000} | **No → hay una discrepancia** de −5 (sin liquidar) o de +1.000 (liquidada) |

**Ejemplo 2: duplicado sin resolver.**
- Gasto manual −50 del 12/11, sin `fecha_valor`.
- El extracto trae −50 del 12/11, **liquidado**, sin vincular.
- **Sin eliminar duplicados**, la base ya incluye el −50 del extracto y el manual está en U'. El caso «el manual también está liquidado» **lo resta dos veces** → saldría un falso r posible = r₀ + 50.
- **Con la regla:** el tramo aparece como «**pendiente de revisar un posible duplicado**» y no se calcula ningún residuo.
- **Al vincularlos** (`confirma`), el manual recibe `fecha_valor` y sale de U' → r = r₀, exacto.

## 3. Qué puede ser una atestación

**Principio:** una atestación es **un saldo que afirma una fuente**. **Un saldo que calcula Palanca a partir de movimientos nunca es una atestación:** convertirlo en una haría r = 0 por definición, que es un **tapón** (N5).

| Fuente | ¿Es una atestación? | Precisión | ¿Ancla? | ¿Puede dar «verificado» (D51)? |
|---|---|---|---|---|
| Extracto con movimientos **sin** saldo | **No** (solo da observaciones de movimientos) | — | — | — |
| Extracto con saldo **inicial y final** | **Sí, dos:** inicial = al cerrar el día anterior al periodo (D41) · final = al cerrar el último día | exacta | Sí | Sí |
| | Además: **comprobación interna** (inicial + Σ movimientos del extracto = final). Si falla, el extracto está incompleto y sus atestaciones **no anclan** hasta revisarlo | | | |
| Extracto con **saldo diario** o acumulado | **Sí**, una por día (el saldo después del último movimiento de ese día) | exacta | Sí | Sí |
| Captura del bróker o del banco | **Solo si** se identifica el **tipo** (liquidado o contable) **y** la **fecha o el instante** | exacta, si se cumple · si no, aproximada | Si es exacta y liquidada | Solo si es exacta |
| | Si es el **disponible**: solo una **comprobación** frente a C − autorizaciones (D63''') | — | No | No |
| Saldo escrito a mano | **Sí** | **exacta** solo si el usuario confirma «es el saldo que ves ahora en tu banco» (con su instante); si no, **aproximada** (D52) | Exacta: sí. Aproximada: solo si se confirma | Solo si es exacta |
| Ajuste antiguo reconstruido (D58: `reconstruida`) | **Sí**: es la **declaración real** de un usuario, reconstruida a partir de la diferencia que se guardó. **No es un saldo calculado** | reconstruida | Solo si se confirma en la migración | **Nunca** |
| Saldo **reconstruido a partir de movimientos** (calculado) | **No. Nunca** | — | — | — |

**Compatibilidad:**
- **D34:** una cuenta sin saldo inicial se ancla con la primera atestación de esta tabla.
- **D49:** la cuenta histórica L usa las atestaciones `reconstruida`.
- **D51:** «verificado» exige una atestación `exacta`.
- **D52:** el saldo del alta es `aproximada`.

**No hay ningún conflicto.**

## 4. D68: las valoraciones, definidas con precisión

**Tres fechas:**
- **`fecha_valoracion`:** a qué momento corresponde el precio (por ejemplo, el valor liquidativo del 19/11).
- **`fecha_publicacion`:** cuándo lo publicó la fuente (20/11).
- **`recibido_en`:** cuándo lo recibió Palanca.

**La regla general** (igual para todos los activos):

```
E(D) = la fecha de valoración programada más reciente cuya publicación esperada ≤ D
al_dia(D) ⇔ fecha_valoracion ≥ E(D)
```

**Lo que se configura** (por activo, por mercado o por fuente; no hay umbrales universales):
- **`ritmo`:** diario, semanal, mensual o irregular;
- **`retraso_publicacion`:** en días hábiles;
- **`calendario`:** de lunes a viernes por defecto, sin festivos (es conservador).

La clase solo da **valores por defecto**: cotizado = diario con retraso 0; fondo = diario con retraso 1–2. Un fondo semanal o mensual **se configura en el propio activo**. **Si el ritmo no se conoce**, no puede estar «al día»: queda `ritmo_desconocido` y se muestra con su fecha.

| Caso | Regla |
|---|---|
| Cotizado frente a no cotizado | Un no cotizado (ilíquido, tasación) es **siempre `estimada`**: nunca entra en «mercado» |
| **Valoración parcial** (`valor_posicion` que cubre menos unidades de las que hay) | Solo cuenta para las unidades que cubre. El resto queda **sin valorar**. La posición no está entera «al día» |
| `precio_unitario` | Vale para **todas** las unidades del activo en esa cuenta |
| **Las unidades no coinciden** con los lotes | `inconsistente` + discrepancia de posición. **No se deduce** un precio = valor / unidades observadas para valorar las unidades propias hasta resolverlo |
| **Pasivos** | Bolsas negativas (§8) al **nominal** (el saldo anclado), con el signo una sola vez. Sin valoración de mercado (aplazada). Entran en PM con su signo |
| Una fuente deja de enviar precios | Las valoraciones pasan a `desfasada` por E(D). Aviso «la fuente X no envía precios desde el dd/mm». **Nunca** se extrapola. El usuario puede dar un precio manual con su fecha |

**«PM determinable», definido en dos niveles:**

```
PM_mercado determinable en D (sobre las cuentas declaradas) ⇔
  (i)   toda posición abierta cotizada está al_dia en D (precio_unitario, o valor_posicion con las unidades iguales);
  (ii)  el efectivo de cada cuenta es único (sin «conciliación pendiente» ni duplicados sin revisar);
  (iii) no hay posiciones inconsistente / sin_fecha / sin_valorar / ritmo_desconocido.
PM_total determinable ⇔ lo anterior + no hay activos estimada abiertos + D29 (todas las cuentas declaradas).
```

**En pantalla:**

| Situación | Etiqueta |
|---|---|
| Se cumple PM_total | «**Patrimonio a mercado: X**» |
| Se cumple solo PM_mercado | «A mercado: X · **más activos con valor estimado: Y** (no de mercado)» |
| No se cumple ninguna | «A mercado: X **de lo valorado al día**» + la lista de lo que falta, con su último valor y su fecha |
| En ningún caso | «Total» sin que se cumpla PM_total |

## 5. D69: los lotes de apertura y el FIFO

**El caso:**
- Corte: 01/09.
- Lote de apertura: 5 unidades, coste desconocido, intervalo de adquisición **(−∞, 01/09]**.
- Lote fechado: 3 unidades el **15/08**, intervalo [15/08, 15/08].
- Venta de 4 unidades.

**¿Es la apertura anterior al lote del 15/08? No se puede afirmar.**
- Los intervalos **se solapan** (15/08 ∈ (−∞, 01/09]).
- Además, el lote de apertura puede **agrupar varias compras**, unas anteriores al 15/08 y otras posteriores. Cualquier número k ∈ {0, …, 5} de sus unidades pudo ser anterior al 15/08.

**Órdenes posibles para la venta de 4:**

| Hipótesis | Consumo | Realizado |
|---|---|---|
| Todo el lote de apertura es anterior | 4 de apertura (sin coste) | No calculable |
| Todo el lote de apertura es posterior | 3 del 15/08 (coste conocido) + 1 de apertura | Una parte se puede calcular |
| k unidades de apertura son anteriores (1 ≤ k ≤ 3) | Combinaciones intermedias | Varía |

**[X] El error:** D69 decía «los lotes de apertura van primero». **Solo es cierto frente a los lotes fechados *después* del corte.**

**La regla corregida:**
- Cada lote tiene un intervalo de adquisición:
  - apertura: (−∞, corte];
  - fechado: [fecha, fecha];
  - entrado sin fecha: (−∞, fecha de entrada].
- **El orden entre dos lotes solo se fija si máx(A) < mín(B).**
- **Fase 1 (D69'):** una venta que **pueda** consumir dos o más lotes de orden no fijado → la asignación queda **pendiente**:
  - el efectivo entra como traspaso neutro (B);
  - se muestran B y PM;
  - **no hay ningún realizado ni ningún rango de PCq**;
  - hasta que el usuario dé fechas (y, si el lote de apertura agrupa compras, que lo **divida en lotes fechados**).
- **Sin asignaciones incorrectas:** solo se asigna cuando el orden está demostrado.

## 7. Resultado

### 7.1 Errores de la respuesta anterior

1. **E2:** «r ∈ [−1.000, 0]» para una compra → es **{0, +1.000}**.
2. **El intervalo como regla de «puede cuadrar»** daba resultados falsos (r₀ = −300, x = −1.000).
3. **Lados tratados como independientes** cuando se liquidan juntos → escenarios imposibles (ejemplo 1 de la sección 2).
4. **Conciliar sin haber eliminado antes los duplicados** → falsos residuos (ejemplo 2).
5. **D69:** «la apertura va primero» es falso frente a los lotes fechados antes del corte.
6. **D68:** se mezclaban la fecha de valoración y la de publicación; faltaban la valoración parcial, los pasivos, la fuente que deja de publicar y una definición completa de «PM determinable».
7. **D66':** faltaban el entorno de ejecución, la zona horaria, el reloj del servidor, las migraciones de solo añadir y quién ejecuta Q1.

### 7.2 Correcciones de diseño

- Conjunto exacto de residuos posibles, con un límite de 20.
- Unidades de liquidación.
- Eliminar duplicados antes de conciliar.
- La tabla de qué es una atestación.
- E(D) con ritmo y retraso por activo.
- PM en dos niveles.
- Intervalos de adquisición para todos los lotes (también los anteriores al corte).
- La tabla de reproducibilidad.

r(S) = r₀ − Σ_{j∈S} x_j ;  R_posibles = {r(S) : S ⊆ U'} ;  «puede cuadrar» ⇔ 0 ∈ R_posibles
